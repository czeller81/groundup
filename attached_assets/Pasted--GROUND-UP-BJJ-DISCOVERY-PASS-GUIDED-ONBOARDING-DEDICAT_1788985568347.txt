# GROUND UP BJJ — DISCOVERY PASS GUIDED ONBOARDING + DEDICATED FUNNEL REPORTING

The Ground Up Discovery Pass campaign is live.

Current evidence shows:

- The Discovery Pass ads are delivering.
- The public Discovery Pass landing page and signup route are reachable.
- Recent users have successfully created member accounts.
- The major observed drop-off is AFTER account creation:
  - accounts created
  - but required forms not completed
  - pass not activated
  - class not booked
- The existing campaign reporting is still partly oriented around an older lead-form funnel and does not cleanly represent the Discovery Pass member-account journey.
- Some internal campaign/session data has also indicated social traffic landing on `/` rather than the intended Discovery Pass route, so destination attribution and funnel reporting must be verified precisely.

Your task is to improve the Discovery Pass post-signup experience and create a dedicated Discovery Pass funnel report.

This is a production funnel optimization task.

Do not redesign the entire portal.

Do not change Discovery Pass legal requirements.

Do not change class entitlement rules.

Do not change campaign creative.

Do not alter membership pricing.

Do not modify unrelated member flows.

Use the smallest production-safe changes necessary.

---

# 1. PRIMARY GOALS

Complete these two objectives:

## A. Guided Discovery Pass onboarding

After a user creates an account through the Discovery Pass acquisition flow, make the next required action unmistakable.

The intended guided journey is:

DISCOVERY PASS LANDING PAGE
→ CREATE ACCOUNT / LOGIN
→ COMPLETE REQUIRED FORMS
→ ACTIVATE DISCOVERY PASS
→ BOOK FIRST CLASS

The member should never have to infer what to do next from a generic portal dashboard.

## B. Dedicated Discovery Pass funnel reporting

Create a clean campaign/funnel view measuring the actual Discovery Pass member journey:

Landing Page Viewed
→ CTA Clicked
→ Account Created
→ Required Forms Started
→ Required Forms Completed
→ Discovery Pass Activated
→ Class Booked

Do not mix this with the legacy lead-form funnel.

When a user enters through:

`intent=discovery-pass`

- as a dedicated onboarding view
- as a Discovery-specific dashboard state

# 7. FORMS START TRACKING

Current reporting needs an explicit milestone between account creation and forms completed.

Add a dedicated event for:

`discovery_forms_started`

Define it carefully.

It should fire when a Discovery Pass user actually begins interacting with a required form, not merely when the forms page loads.

Examples:

- first field interaction
- first form edit
- first required-form open if that is the project’s established analytics convention

Choose one consistent definition and document it.

Do not generate duplicate starts on every keystroke.

---

# 8. FORMS COMPLETION TRACKING

Preserve the existing:

`discovery_waiver_completed`

or equivalent current event.

Verify whether the current event means:

- one form completed
or
- all required forms completed

This distinction matters.

If the current event fires once per required form, preserve it but also create a clean aggregate milestone:

`discovery_required_forms_completed`

only when all required forms needed for Discovery activation are submitted.

Do not silently change existing analytics semantics.

Document exactly what each event means.

# 19. CONSENTED VS TOTAL TRAFFIC

The existing reporting contains consent-aware analytics, and that can make totals look inconsistent.

The new Discovery report must clearly distinguish:

- total application/database-observed funnel events
- consent-gated analytics events
- ad-platform metrics if imported/entered separately

Do not combine unlike denominators without labeling them.

For example:

**Application funnel**
Account created: 3

**Consented analytics**
Tracked sessions: 44

These are different data populations.

Make that obvious.
