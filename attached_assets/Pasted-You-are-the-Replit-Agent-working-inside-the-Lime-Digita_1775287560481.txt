You are the Replit Agent working inside the Lime Digital VIBE OS codebase.

Your task is to refactor the AI Conversion Audit recommendation system so it becomes vendor-neutral by default and no longer leaks Lime Digital / VIBE OS internal product language into third-party website audits.

This is a trust-critical product fix. Do not make a shallow copy edit. Audit the recommendation pipeline, prompt templates, fallback logic, output rendering, and UI separation, then implement the complete fix end-to-end.

==================================================
PRIMARY GOAL
==================================================

When the Conversion Audit analyzes an external or third-party website, the audit must:

1. Diagnose the site objectively
2. Recommend the right execution path in neutral language
3. Avoid self-promotional leakage in the main recommendation
4. Never imply Lime Digital / VIBE OS is the only or required next step
5. Only mention Lime / VIBE OS / Build Packs / Replit / internal dashboard routes in a clearly separated OPTIONAL section, and only when appropriate

The core rule is:

THE MAIN AUDIT MUST BE VENDOR-NEUTRAL.
ANY INTERNAL LIME ROUTING MUST BE CLEARLY SEPARATED AS OPTIONAL.

==================================================
NON-NEGOTIABLE RULES
==================================================

1. Do NOT mention “Lime dashboard,” “Build Packs,” “Replit,” “VIBE OS,” or internal product routes in the main audit diagnosis or main recommendation block for third-party sites.
2. Do NOT let internal product upsell language contaminate neutral recommendations.
3. The audit must never sound like it always finds a reason to sell Lime.
4. If the user is auditing an external domain, the primary recommendation must remain product-agnostic.
5. If an optional Lime implementation path is shown, it must be:
   - clearly labeled as optional
   - visually separated
   - subordinate to the neutral recommendation
6. Preserve monetization opportunities without sacrificing trust.
7. Do not break the existing scoring logic, UI flow, or audit generation system.

STEP 2 — DEFINE CLEAR MODES
==================================================

Introduce explicit recommendation modes.

Required modes:
1. Vendor-neutral audit mode
2. Optional Lime implementation mode
3. First-party / Lime-site audit mode

--------------------------------------------------
MODE 1 — VENDOR-NEUTRAL AUDIT MODE
--------------------------------------------------

Use this when auditing:
- third-party sites
- client sites
- unrelated business websites
- any domain not owned/operated by Lime Digital or the user’s VIBE OS property if that distinction exists

This mode must:
- diagnose objectively
- recommend neutral solutions
- describe the needed funnel/system/site changes in generic terms
- avoid internal product references in the main recommendation

Allowed language:
- booking funnel
- landing page
- onboarding sequence
- CRM
- scheduler
- checkout flow
- trust layer
- lead routing
- email/SMS reminders
- local SEO page
- service funnel
- waitlist flow
- intake sequence
- production-ready web app
- authenticated portal
- customer dashboard

Disallowed in main recommendation:
- Lime dashboard
- VIBE OS
- Build Pack
- Replit prompt
- internal plan names
- “go to Lime”
- “select X pack in dashboard”
- anything sounding like forced self-routing

--------------------------------------------------
MODE 2 — OPTIONAL LIME IMPLEMENTATION MODE
--------------------------------------------------

This mode may appear only as a separate, optional section when the user is inside your product and it is contextually useful.

This section must be clearly labeled with phrasing like:
- Optional: Build this in VIBE OS
- If you want to implement this inside Lime Digital
- Optional implementation path in VIBE OS

This section can mention:
- relevant pack names
- internal workflow names
- dashboard steps
- product-specific implementation pathways

But it must remain:
- clearly optional
- not merged into the main audit diagnosis
- not framed as the only correct next step

--------------------------------------------------
MODE 3 — FIRST-PARTY / LIME-SITE AUDIT MODE
--------------------------------------------------

If the site being audited is a Lime Digital / VIBE OS property, it is acceptable for recommendations to refer directly to internal product structures, because it is your own product ecosystem.

Even then:
- keep the diagnosis honest
- do not let upsell language replace real analysis
- keep recommendations credible and operational

- audited domain

- whether the site belongs to Lime Digital / VIBE OS
