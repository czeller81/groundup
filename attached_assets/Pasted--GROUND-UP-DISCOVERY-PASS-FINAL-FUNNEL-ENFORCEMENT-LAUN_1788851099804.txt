# 1. CURRENT KNOWN CRITICAL ISSUE

The existing endpoint:

`/api/portal/discovery/claim`

currently allows Discovery Pass activation without enforcing required waiver completion at the API/server level.

This must be corrected.

The intended business sequence is:

LANDING PAGE
→ CREATE ACCOUNT / LOGIN
→ COMPLETE REQUIRED WAIVERS
→ ACTIVATE DISCOVERY PASS
→ BOOK CLASS

The server must enforce this sequence.

UI-only enforcement is insufficient.

* member identity

* whether multiple waivers must be completed
* whether previously completed valid waivers satisfy the requirement

Reuse the existing source of truth.

# 3. ENFORCE WAIVER COMPLETION SERVER-SIDE

Update the Discovery Pass claim/activation path so the server verifies all required waiver conditions before activation.

Expected behavior:

## Valid member

Required waivers complete
→ activation allowed

## Missing required waiver

Required waiver incomplete
→ activation denied

Return an appropriate existing application/API error response.

Do not issue Discovery Pass entitlements.

Do not start the seven-day validity period.

Do not partially mutate the member record.

# 4. FAIL CLOSED

If waiver status cannot be safely determined because of:

* database error
* inconsistent record
* unknown form state
* missing required data

the Discovery Pass must NOT activate.

Do not assume completion.

Do not silently bypass the requirement.
